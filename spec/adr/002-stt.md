# ADR-002: Spracherkennung (STT)

**Status:** Vorgeschlagen, Spike 0.3 · **Bezug:** /LL100/, /LF113/, /LL400/

## Kontext

Kaiwa muss Lernendensprache erkennen, **ohne sie glattzubügeln**. Ein STT, das おばさん hört, wo おばあさん gemeint war und おばさん gesagt wurde, ist richtig. Eines, das die gemeinte Form errät, versteckt den Fehler. Lokal muss es auf dem Framework 13 (CPU/iGPU) laufen.

## Optionen

| Option | Lizenz | Für | Gegen |
|---|---|---|---|
| **whisper.cpp** (`whisper-rs`), large-v3-turbo / small | MIT | reif, schnell auf CPU, Wort-Zeitstempel, Konfidenzen | glättet Lernendenfehler (Sprachmodell-Effekt), Halluzinationen bei Stille |
| **ReazonSpeech** (k2/ESPnet, ONNX) | Apache-2.0 | auf Japanisch spezialisiert, sehr gute CER | Integration in Rust aufwendiger (ONNX Runtime) |
| Cloud: Azure Speech, Google, OpenAI | proprietär | Streaming, niedrige Latenz; Azure hat Aussprachebewertung für ja-JP (ADR-005) | Audio verlässt das Gerät, Kosten |

## Empfehlung

Lokal **whisper.cpp** als Standard (Modell nach Hardware) und **ReazonSpeech als Herausforderer** im Spike. Dekodierung mit Temperatur 0, ohne Kontext-Prompt und mit Token-Wahrscheinlichkeiten, damit unsichere Stellen nachgefragt statt korrigiert werden. VAD mit Silero (ONNX, MIT). Cloud nur als Opt-in.

## Spike 0.3 (Abnahme)

- **Korpus:** 50 Sätze, je dreimal gesprochen:
  - korrekt
  - mit eingebauten Lernendenfehlern (Personas)
  - mit Störgeräusch nach `snr_db`
- **Messwerte:** CER, **Fehlertreue** (wie viele eingebaute Fehler bleiben im Transkript erhalten), Latenz p50/p95 auf Referenzhardware.
- **Ziel:** CER ≤ 12 %, Fehlertreue ≥ 85 %.
